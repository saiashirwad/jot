# Selected text and Source capture on macOS

Research for [ticket #4](https://github.com/saiashirwad/jot/issues/4), 2026-09-30. Scope: research, not implementation. Domain terms follow [CONTEXT.md](../../CONTEXT.md).

## Decision

Use **Accessibility (AX) first**, snapshot Source before activating jot, and use a **guarded Copy fallback** only when AX cannot answer. Excerpt may be empty. Source URL is optional: prefer AX metadata; optionally use browser-specific Apple events if permission is already granted. Never navigate the browser or copy its address bar to get a URL.

Two requirements cannot be universal guarantees:

- macOS has no “selected text in every app” API: AX depends on what the target exposes. Copy also depends on the app and can copy something other than a selection.
- We can restore all materialized pasteboard item/type/data bytes, **not the exact clipboard state**: owner, changeCount, lazy providers, file promises, clipboard history and concurrent writers cannot be rolled back. If literal exact preservation is mandatory, disable Copy fallback; AX-only capture still allows an Annotation with an empty Excerpt. The practical v1 recommendation is best-effort content preservation with conservative refusal when a complete snapshot cannot be made. [1–4]

## Capture transaction: finish before showing the pop-up

The following is a proposed policy, not an OS timing guarantee.

1. Serialize capture requests. At the hotkey edge record time, `NSWorkspace.sharedWorkspace.frontmostApplication` (PID, bundle identifier, localized name), and create an AX application element for that PID. Do not activate jot, open a panel, focus a text field, or display a permission prompt during capture. Use the app AX element's `AXFocusedWindow` → `AXTitle` and `AXFocusedUIElement`; validate the latter's PID. Store copied strings, not a pointer that will be re-queried after jot activates. Missing title is allowed. [1,5]
2. Query the focused element's `AXSelectedText` with `AXUIElementCopyAttributeValue`. Check the error, non-null value, and CF type before treating it as a CFString. Nonempty text wins. A reliable empty string/zero-length `AXSelectedTextRange` means empty Excerpt, not “try copying the current line.” Unsupported/no-value/cannot-complete means **unknown**, not empty. `AXValueGetValue` decodes a CFRange; its indices are not UTF-8 byte indices. Do not use the whole `AXValue` as though it were the selection. [1,6]
3. If focus is a wrapper, inspect a small bounded set of parents and relevant focused-window web/text descendants. Prefer the focused content's selection; never scan unrelated windows and take the first nonempty selection. Browser pages can expose selection on a web area rather than the immediate focused node. A bounded adapter is safer than an unrestricted full-tree walk. WebKit text-marker APIs are possible later, but are not necessary for the first pass. [7,8]
4. In the same pre-activation phase capture URL as described below. Use an overall deadline and `AXUIElementSetMessagingTimeout` on queried elements (or the system-wide element to set the client default). Start with ~100 ms per AX call and a ~300 ms AX phase; these numbers require tuning, not a documented latency promise. Stop traversal when the overall budget runs out. AX calls are synchronous and can fail when an app is busy. [1]
5. If selection remains unknown, decide whether Copy is safe: permission already available, not a secure text field, source still frontmost/focused, hotkey modifiers released, clipboard snapshot complete, no other capture in flight. Otherwise leave Excerpt empty with an internal reason (`unsupported`, `permission_denied`, `timeout`, etc.). Do not log captured content.
6. Run the Copy transaction below. Recheck PID/window/focus before posting; discard results if the source changes. There is no atomic lock on another app's focus or document, so this reduces rather than eliminates races.
7. Restore when safe, release AX/CF objects, freeze Excerpt + Source, then show jot's pop-up. Pop-up code must consume that frozen snapshot. A URL that could not be captured in time stays absent rather than being fetched from a newly active tab later.

Onboarding should request Accessibility and optional Automation permission separately from capture. A denied permission should not prevent recording a Note with an empty Excerpt. AX `Copy`/`Create` results require `CFRelease`; borrowed `Get` results do not. [1,9]

## Copy fallback and clipboard preservation

### Snapshot first

Read general pasteboard `changeCount = c0`, then enumerate **every `pasteboardItems` item in order**, its `types`, and `dataForType:` for every advertised type. Copy the returned NSData bytes into owned storage (preserve zero-length data, private types, RTF, images, file URLs, etc.). Check changeCount again. If it changed, retry once or abort; if any advertised representation returns nil, abort. Do not flatten the board to `stringForType:` or save just its first item. Put bounds on memory and elapsed time; exceeding bounds must skip fallback rather than silently dropping types. [2–4]

Reading can invoke a lazy data provider. A file promise describes future behavior, not just a reproducible byte blob. Saving all advertised bytes cannot recreate the original provider or its lifetime. Skip known file-promise/provider-dependent cases; recognize that detection cannot prove universal restorability. A slow provider also defeats a hard synchronous time bound, so isolate risky materialization from the UI path and never mutate after abandoning that transaction. [2,4]

Modern macOS also has pasteboard access policy: SDK `NSPasteboardAccessBehavior` documents ask/allow/deny and the user-originated-paste exception. An Annotation hotkey is not demonstrably a system-authorized Paste. Do not assume background clipboard reads cannot prompt, or that AX permission grants pasteboard read permission. Configure/verify pasteboard access during onboarding; refuse fallback if data cannot be obtained. The private-board test below does **not** test general-board privacy. [3]

### Post Copy, then wait for evidence

- Do not clear the general pasteboard or place a sentinel before Copy. Preserve its contents while waiting.
- Recheck source and `changeCount == c0`. Wait for physical Option/Control/Command/Shift release (bounded wait; skip on timeout) so ⌥E/⌥G does not turn Copy into another shortcut. Do not inject synthetic key-up events for the user's held keys.
- Create C-key down/up using `CGEventCreateKeyboardEvent`, explicitly set `kCGEventFlagMaskCommand` on the pair with `CGEventSetFlags`, then `CGEventPost(kCGHIDEventTap, ...)`. Release both events. Virtual keycode 8 is the ANSI C position; validate keyboard-layout behavior in the prototype and support remapping rather than claiming all layouts work. `CGEventPost` is void: returning from it is not proof the target copied. `CGPreflightPostEventAccess` checks posting access; `CGRequestPostEventAccess` belongs in onboarding. This is Accessibility/post-event access, not a need to record the screen. Input Monitoring for a hotkey/event tap is a separate design question. [10]
- Poll changeCount on a timer, not a fixed blocking sleep. Suggested initial settings: 10–20 ms polls, 300–500 ms total deadline. If it never differs from `c0`, return **no copy observed**. Do not read the old clipboard as an Excerpt and do not rewrite it unnecessarily.
- Once it changes, capture a stable copy of the new text (read count before/after). Allow a short bounded settling interval for multi-step writers. If there is no text representation, Excerpt is empty. Equality of text to the old clipboard is irrelevant: selecting the same text twice can still be a valid Copy. [2]

**changeCount does not prove selection or identify the writer.** No change may mean no selection, blocked events, busy app, disabled Copy, or a timeout. A change may be another process, clipboard manager, or an app copying a current line without a selection. VS Code explicitly supports `emptySelectionClipboard`; therefore don't invoke fallback when AX reliably reports a caret/empty range, and treat fallback-only results as unverified selection. A universal “nothing selected” detector is not available. [2,11]

### Restore, but do not overwrite a newer clipboard

Construct **fresh** NSPasteboardItem objects, `setData:forType:` with all saved bytes, preserve item order, `clearContents`, then `writeObjects:`. Reusing items returned by `pasteboardItems` is wrong: Apple documents that already-associated items cannot be written again. An originally empty board restores via clear alone. [4]

Before restoration, check that the current changeCount still equals the copied version just read. If another change was observed, preserve the newer board and report that restoration was skipped. This check is not an atomic compare-and-swap: another writer can race between check and clear. Nor can it prove the first change was caused by our Copy. There is no public pasteboard transaction/lock here. A delayed Copy after timeout can still replace the board; there is no event cancellation/Copy completion acknowledgement. Never schedule a blind delayed restore. These limits are why “exactly” must not appear as a product guarantee. [2,3,10]

Clipboard managers may see both temporary copied content and the restoration; existing history cannot be undone. Byte restoration was locally tested for two items with text and a custom binary type, not promised resources or third-party clipboard managers.

## Browser URL and permissions

**AX route (default):** inspect the captured focused window's `AXDocument` and relevant active web area's `AXURL`. AXDocument describes a document URL; AXURL may instead describe a link or image, so never use an arbitrary focused link as the page Source. Validate value type (CFString or CFURL as appropriate), preserve the actual scheme, and prefer the active document/web area. AX hierarchy/availability depends on the app; a blank/missing URL is valid. Uses Accessibility permission, no Apple-event Automation grant. No address-bar focus, keystrokes, or screen capture required. [1,7,8,17]

**AppleScript / ScriptingBridge (optional fallback):** direct browser scripting retrieves browser-owned active-tab state, rather than relying on AX hierarchy. Safari dictionary was inspected locally: `current tab` on window and `URL` on tab. Chromium's dictionary uses `active tab` and `URL`. Example read-only queries are `tell application "Safari" to get URL of current tab of front window` and `tell application "Google Chrome" to get URL of active tab of front window`. Only query the already-running, captured app and validate focus before/after; never launch a browser just to get a URL. Arc requires inspecting its own dictionary/version first. [15,18]

Both AppleScript (e.g. `NSAppleScript`) and ScriptingBridge send Apple events. ScriptingBridge is **not** a permissions bypass; Automation consent is per sender/target. Include `NSAppleEventsUsageDescription` for the app; hardened runtime Apple-events entitlement and sandbox constraints apply when those deployment modes are used. Use bounded Apple-event timeouts and no consent prompts in the capture path. Direct property reads do not require “Allow JavaScript from Apple Events”; JS execution would be a different feature and is not recommended here. Calling `osascript` complicates process identity/TCC attribution and is unnecessary for the eventual Odin app. [18–20]

An unsigned bare binary's long-term permission identity is not established by this research. The local trust probe returned false; packaging/permissions research must settle tmux versus an app bundle. Do not infer that granting a terminal permission necessarily grants the shipped jot binary the same access.

## What was actually tested

Machine: arm64 macOS **27.0 (26A428)**, Xcode SDK selected by `xcrun --show-sdk-path`, Odin version above. Do not generalize these results to macOS 15/26 without testing.

1. **Odin compile/run:** custom ApplicationServices and CoreGraphics foreign imports linked successfully; `AXIsProcessTrusted() = 0`, `CGPreflightPostEventAccess() = false`; creating (not posting) a C-key CGEvent returned non-nil. An NSPasteboard private instance created with `intrinsics.objc_send(^Foundation.Pasteboard, Foundation.Pasteboard, "pasteboardWithUniqueName")` returned non-nil. This validates basic arm64 ABI/framework/ObjC invocation, not full capture.
2. **Native Objective-C throwaway:** private unique pasteboard with two items, each plain text plus custom binary bytes including NUL and 0xff; snapshot all types/bytes, replace, reconstruct fresh items, restore. All item/type/data bytes compared equal; changeCount changed. Output: `all items/types/bytes restored=1 count changed=1`. No general clipboard was touched.
3. **Native NSTextView:** set text `alpha beta gamma`, selected NSRange(6,4); accessibilitySelectedText returned `beta`, selected range length 4. This tests native producer behavior, not permission-gated cross-process AX transport.
4. **Static audits:** searched Odin bindings; read Apple SDK AX/CG/NSPasteboard headers, installed Safari scripting dictionary, upstream Ghostty/iTerm2/WebKit/Chromium/VS Code code and first-party docs. These are source findings, not runtime app coverage.

Throwaway files stayed outside the repository and are not committed. No jot build, generated input, permission request, or browser automation was performed. Live AX/Copy timing, general clipboard privacy, browser URLs, Arc scripting, and TCC identity remain unconfirmed. Those limitations do not prevent choosing the capture architecture, but they preclude claiming “works in any app.”
